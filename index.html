排查清单 · 5 步

www.abg33.net 访问异常排查清单（DNS / 浏览器内核 / 扩展）

访问某个站点时出现打不开、加载慢、白屏、反复跳回登录页，绝大多数情况不是站点本身的问题，而是链路、缓存或浏览器策略的差异。下面这套清单按「从省事到费力」排序，每一步都能独立验证。

01 先确认是不是本地出口问题

把 Wi-Fi 关掉，切到手机流量，用同一个地址再打开一次。

  • 流量下正常 → 问题在本机宽带出口，与站点无关
  • 流量下同样异常 → 继续往下排查
这一步能排除六成以上的误判，成本几乎为零。

02 DNS 解析是否返回了过期记录

部分地方运营商的默认 DNS 会缓存已下线节点的记录，表现为「域名能解析、但连不上」。用命令行确认：

bashnslookup www.abg33.net 223.5.5.5
ping www.abg33.net

如果 223.5.5.5 返回的 IP 与本地默认 DNS 返回的不一致，把设备 DNS 改成 223.5.5.5 或 119.29.29.29 后重试。

03 缓存里还留着上一版的跳转逻辑

浏览器会把 301/302 缓存下来。站点换过地址后，旧缓存可能一直把你送往已失效的路径。

  • Chrome / Edge：Ctrl + Shift + R 强制刷新
  • 手机端：设置里清除「站点数据」，而不是只清「缓存」
用无痕窗口打开是最快的验证方式：无痕能开，说明是缓存问题。

04 浏览器扩展与内核策略

这几类扩展最容易误伤：

扩展类型表现处理
广告拦截（uBlock / AdGuard）页面停在加载动画、白屏把站点加入白名单
隐私保护（严格模式）登录后被立刻退回防护等级调为「均衡」
省流 / 云加速反复要求重新登录关闭省流与云加速

内核差异也常见：微信内置浏览器会拦掉带 X-Frame-Options 的页面，UC 与 QQ 浏览器的云加速会改写 UA 并剥离 Cookie。换系统自带浏览器验证一次，就能定位是不是容器问题。

05 域名拼写

这一条最容易被忽略。network 写成 netwoork、.net 与 .network 混用，都会指向完全不同的服务器。逐字核对地址栏。
